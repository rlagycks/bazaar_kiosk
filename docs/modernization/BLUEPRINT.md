## 목표·현재 사실·범위

현재 Django와 바닐라 JS를 유지하는 점진적 현대화를 권고한다. 분석에서 주문 생성 atomic,
서버 가격 스냅샷, 정상 PG 번호 고유 할당, 목록 사전 로딩은 보존할 기반으로 확인했다.
반면 익명 API 변경, PG0019/0020 설치·업그레이드 실패, 중복 요청, 금액/상태/통계 오류는
프레임워크를 재작성해도 따로 해결·검증해야 한다. 초기 분석 당시 테스트0인 상태의 전면 재작성은
데이터 이전·권한·금전 계약을 동시에 다시 증명하게 만들어 현 증거로 정당화되지 않는다.
부분 프런트엔드 교체는 API 안정화 후 별도 D-009에서 재평가한다.

- 근거: [분석 보고서](ANALYSIS_REPORT.md), [위험 등록부](RISK_REGISTER.md),
  [기준선](BASELINE.md), [결정 기록](DECISIONS.md), [작업 로그](WORKLOG.md).
- 확정 방향: D-018 자체 SSE, D-020 Compose PostgreSQL, D-023 주문·서빙 / 주방 / 관리자.

  **디자인 수정·Figma 적용은 추후 별도 작업**이다. [Figma 초안](UI_UX_REDESIGN.md)은 참고만 한다.
- EC2·단일 호스트는 D-021 후보다. SSE 영속 전달 상세 D-019, 데이터 이전 D-022,
  지상·부스 제거 D-024, 금전/번호/권한 정책은 미확정이다.
- 역할5개를3개로 합치거나 통계 조회자를 Django 관리자 권한으로 승격하지 않는다.

## 병렬 작업과 통합 책임

통합 책임자는 현재 현대화 주 담당 에이전트다. 실제 구현 시작마다 WORKLOG에 사람/에이전트와
파일 소유권을 기록한다. 한 하위 단계는 하나의 검토 가능한 변경 단위를 목표로 한다.
아래 범위를 넘으면 구현 전에 쪼개되, 위험을 누락하거나 끝난 검사를 반복해 부풀리지 않는다.

- 2A의 테스트/SQLite 설정과1A의 PG/Compose fixture는 파일을 분리해 병행 가능하다.
- 2A 이후3의 API 인가와4A1의 환경 비노출은 소유 파일이 다를 때 병행 가능하다.
  3·8A가 함께 api.py를 변경한다면 작업 순서를 직렬화하거나 명시적 통합 담당이 통합한다.
- 10A runtime/proxy 검증은9/10B 준비와 파일이 겹치지 않으면 병행 가능하다.
- 5/6/7/10B의 schema·transaction·writer 변경은 **데이터/주문 통합 담당 한 명**이 조정한다.
  revision 잠금은10B에서 추가하더라도5부터 도메인 잠금 순서와 전체 명령 재시도 경계를 남긴다.
- 8B/10C snapshot은 조회 담당,10D1 허브는 실시간 담당이 맡되 프로토콜 통합은 주 담당이 책임진다.
  10D2와11의 연결·폴링·재조회 scheduler는 공동 편집하지 않는다.
- 12A3의 schema·writer 동결·restore·세션/SSE generation은 데이터 이전 통합 담당 한 명이 관리한다.
- G는 계획과 독립이며 원격 설정 변경 없이2A를 진행할 수 있다. UI는 현대화 릴리스 필수 경로가 아니다.

| V-BROWSER | 합성 계정/DB, 휴대폰 주문·서빙/PC 주방·관리자, 실제 클릭·네트워크·키보드/터치/스크린리더. Figma 캡처는 통과 증거 아님 |
| V-STREAM | 실제 ASGI+proxy HTTP로 첫 프레임/반복 flush·일반 API 병행·disconnect/reload·세션 회수. 단순 iterator/worker import로 대체 금지 |
| V-LOAD | 승인된 버전/CPU/워커/데이터·기기 수와 동일 workload의 전후 SQL/lock/p95/FD/RSS·표시 지연·정확성 |
| V-DEPLOY | 명시적으로 승인된 비운영 배포 대상·가림 처리 환경. config --quiet, app-role DB/TLS/schema readiness, 외부 포트/프록시/헤더/로그 검사 |
| V-RESTORE | 승인된 정제 복사본과 새 격리 대상. 오류0/객체·행·금액·sequence·세션/generation·복원시간·새 쓰기 보존 대조 |

현재 원본에서 사용할 명령은 다음과 같다. PG 명령은 [PG 준비 안내](POSTGRES_TESTING.md)의
전용 Compose·테스트 URL·identity 검사를 먼저 완료해야 한다. 각 단계의 'test …'는 관리 명령의 하위 인수다.

```bash
.venv/bin/python manage.py check --settings=bazaar_kiosk.settings_test
.venv/bin/python manage.py makemigrations --check --dry-run --settings=bazaar_kiosk.settings_test
.venv/bin/python manage.py test orders.tests.test_baseline --settings=bazaar_kiosk.settings_test
.venv/bin/python manage.py test orders.tests.test_migration_paths --settings=bazaar_kiosk.settings_test_pg
docker compose -f compose.test.yaml config --quiet
```

PG 모듈 test_migration_paths는0020 적용 후 성공 경로와 남은 실패를 함께 고정한다. 정확한 사례 수와
명령은 [적용 기록](MIGRATION_REPAIR_REVIEW.md)·[현재 인계](SESSION_SETUP.md)를 따른다.
전체 PG suite의 성공을 현재 인수 조건으로 복사하지 않는다. 앱 테스트는 별도 명령으로 PG에서 실행한다.

데이터베이스/호스트 검증은 환경 이름만 검사하지 않고 실제 연결 identity·권한을 확인한다.
일회용 자원만 정리하며 운영/공유 볼륨에 down -v를 적용하지 않는다.
check/test 명령의 exit0와 실제 테스트 수집·불변 조건 검증을 구분한다.
각 단계는 좁은 실패 회귀→수정→관련 검사→필요한 통합 검사 순서로 검증하고
Fail/Not run을 숨기지 않는다. 보안 통제를 없애거나 빈 PG에 임의 주문/fake 이력을 넣어
통과시키는 방식은 금지한다. 신규 설치와 과거 데이터 업그레이드·원본 restore는 서로 다른 검사다.

각 단계의 **승인된 범위**는 아래 작업 범위와 해당 단계 실행 사용자 지시의 교집합이다.
이번 문서 수정 지시가 아래 구현 범위 전체를 승인한 것은 아니다.
매 단계 인계에는 기준 ref와 실제 diff, 결정 ID, 위험 주 담당/기여 증거, 실행 명령·환경·결과,
미실행 검사, rollback/forward recovery, 다음 관문을 WORKLOG에 기록한다.
현재 최신 보고서 일부는 untracked/modified이므로 새 worktree가 자동 포함한다고 가정하지 않는다.
원격 push/merge·태그·과거 이력 수정·자원 생성·운영 이전은 기존 승인 경계를 유지한다.

- **검증 명령·환경:** V-DOC; git rev-parse HEAD; git diff origin/main..origin/develop; git cat-file -e HEAD:AGENTS.md; 로컬 작업 파일과 기준 ref 비교.
- **마이그레이션·롤백:** 기존 refs/사용자 미커밋 변경 보존; force push/자동 merge/브랜치 삭제 금지.
- **관측·보안·인계:** BK-R025 증거·체크포인트 diff 인계. 원격 승인과 로컬2A 착수를 분리.

<a id="phase-r"></a>
### R — 승인된 운영 전환 실행

- **맥락·목적:** 리허설과 감사만으로 실제 운영 이전 권한은 생기지 않는다.
- **선행 조건:** 12B. **결정 관문:** 정확한 대상·시각·중단·백업·복귀 조건·과금/원격 작업에 대한 별도 사용자 승인.
- **책임·주 위험:** 운영·데이터 이전 통합 담당; 독립 기여/인수 단계.
- **승인 대상 범위·파일:** 승인된 runbook 실행 기록. 이 범위의 구현은 해당 단계 실행 지시 이후다.
- **작업:** 12A3의 검증된 순서로 writer 동결·대조·단일 대상 쓰기·SSE/세션 전환·업무 smoke를 실행한다.
- **인수 기준·기대 결과:** 운영 행/금액/번호·주문→주방→통계 정상, 백업/경보 활성, 원본 보존 기간과 책임자 확정.
- **검증 명령·환경:** 검증된 cutover runbook의 명령/중단 기준 그대로. 실행 시 실제 승인 환경 결과 기록.
- **마이그레이션·롤백:** 새 쓰기 전/후 분기를 따르며 DNS/URL만 원복하지 않음.
- **관측·보안·인계:** 운영 전환 결과·미해결 위험·연락/복구 담당 인계. 이번 작업에서는 미실행.
