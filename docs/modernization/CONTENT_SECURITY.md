# 4B1 — 안전한 화면 렌더링

상태: 구현과 로컬 브라우저 검증. BK-R011의 저장소 쪽 수정이며 운영 인수는 별도다.
디자인 변경은 하지 않았고 화면 구성·업무 흐름은 그대로다.

## 무엇이 문제였나

메뉴 이름·테이블 이름·요청사항은 운영자가 입력해 DB에 저장되고, 화면 JavaScript가
그 값을 받아 HTML 문자열로 조립했다. 그러면 이름이 **마크업으로 해석**된다.

주문 화면은 한 걸음 더 나갔다. 이름을 `onclick` 속성 안의 JavaScript 문자열에 넣고
작은따옴표만 `\'`로 바꿨다. 속성 경계와 문자열 경계 두 겹을 한 번의 치환으로 막으려 한
것이라 역슬래시·줄바꿈·큰따옴표가 들어오면 뚫린다.

## 실제로 확인한 취약점 (2026-09-18)

수정 전 코드에 합성 메뉴 3개를 넣고 실제 Chromium으로 주문 화면을 열었다.

| 저장된 이름 | 수정 전 결과 |
| --- | --- |
| `<img src=x onerror="window.__xss=1">` | **스크립트 실행됨**(`window.__xss === 1`), `<img>` 요소가 페이지에 삽입됨, 이름은 빈칸으로 표시 |
| `A&W <cola> "큰컵"` | `<cola>`가 사라져 `A&W  "큰컵"`으로 표시 — 정상 이름도 깨졌다 |

즉 보안 문제이면서 동시에 표시 버그였다. 공격 문자열이 아니어도 꺾쇠가 든 이름은 깨진다.

## 어떻게 고쳤나

공용 헬퍼 `orders/static/orders/ui/dom.js`(`window.BazaarDom`)를 만들고 두 화면을 옮겼다.

- 값은 `textContent`와 텍스트 노드로만 넣는다. HTML 파서에 문자열을 넘기지 않는다.
- 속성은 DOM API로 설정한다. 이름에 든 따옴표가 속성을 끝낼 수 없다.
- 인라인 `onclick`을 제거하고 컨테이너 한 곳에서 이벤트를 위임 처리한다. 버튼은 `data-id`만
  들고 있고, 이름·가격은 화면이 따로 보관한 목록(`MENU_BY_ID`)이나 장바구니에서 읽는다.
  **핸들러에 운영자 입력이 들어갈 자리가 없다.**
- 공용 `app.js`의 비우기도 DOM 제거로 바꿔, 파서로 가는 쓰기를 남기지 않았다.

주방 화면(`kitchen_supervisor.html`)은 원래 값마다 `escapeHtml`을 적용하고 있어 이번 범위에
넣지 않았다. 대신 그 escape가 유지되는지 회귀로 고정했다. 전체 DOM 전환은 9·11단계다.

`serve.html`은 어떤 뷰도 렌더링하지 않는 미사용 템플릿이라 고치지 않았다. 대신 **다시
참조되면 실패하는 테스트**를 넣었다. 삭제는 11단계의 정리 범위다.

## 검증

| 검사 | 결과 |
| --- | --- |
| 전체 PostgreSQL 테스트 | 163개(마이그레이션16+앱147), skip0 통과 |
| `orders/tests/test_content_security.py` | 9개 통과(인라인 핸들러 부재, 파서 쓰기 부재, 주방 escape 유지, 미사용 템플릿 미참조, API 원문 전달) |
| `scripts/test_dom_helpers.cjs` | 9개 통과(가짜 DOM에서 공격 문자열이 텍스트로만 들어감) |
| 실제 Chromium (390×844 / 1280×900) | 12개 통과 |

브라우저 검사는 합성 DB·합성 계정·로컬 서버로 수행했고 운영 데이터는 쓰지 않았다.
검사 스크립트는 저장소 밖 작업 디렉터리에만 두었으며 서버·DB는 종료·삭제했다.

**검사 자체의 신뢰성 확인:** 같은 검사를 수정 전 템플릿에 돌려 5개가 실패하는 것을 봤다.
처음에는 통과로 보였는데, `--noreload`로 띄운 서버가 템플릿을 캐시하고 있어서였다.
서버를 다시 띄워 비교했고, 그 뒤에야 실패가 재현됐다. 통과만 보고 인수하지 않는다.

## 남은 것

- 주방 화면의 문자열 조립 제거(escape로 방어 중) — 9·11단계
- `serve.html` 삭제 — 11단계
- CSP 헤더: 실제 자산 경로·인라인 스크립트 정리가 선행이라 4B2/12A1에서 다룬다.
  현재 화면은 인라인 `<script>`를 쓰므로 엄격한 CSP를 지금 넣으면 화면이 멈춘다.
- BK-R011은 저장소에서 닫혔고 운영 인수 전까지 Open이다.
