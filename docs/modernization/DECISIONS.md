### D-018 — 브라우저 외부 Realtime을 자체 SSE로 전환

- 상태: accepted (사용자가 직접 지정한 방향)
- 날짜: 2026-09-06
- 결정 제공: 저장소 사용자; 후속 통합 담당은 실시간·백엔드·프런트 담당
- 사용자 지침: “기존에 브라우저에 보내던 방식을 외부 서드파티 연결 안하고 직접 sse 방식으로
  리펙토링도 하려고 … 이것도 같이 분석해서 포함해줘”
- 결정 범위: 브라우저의 Supabase Realtime/CDN SDK 의존을 제거하고 자체 서버 SSE로 대체하는
  방향을 현대화 분석에 포함한다. 현재 실제 교체 화면은 주방이며, 쓰기 명령은 HTTP로 유지하는
  방안을 제안한다. 이 SSE 요청 자체로 카운터의 새 자동갱신이나 DB 호스팅 이전을 추정하지 않았다.
  이후 사용자가 DB 자체 운영을 추가 지정한 내용은 별도 D-020에 기록한다.
- 승인 경계: 이번에는 분석 문서만 수정한다. 코드·스키마·의존성·배포·외부 설정 변경이나
  원격 push/merge를 승인한 것이 아니다. 같은 SSE 방향을 다시 묻지 않는다.
- 결과: D-010의 전송 방식 선택은 이 결정으로 구체화했다. RLS 정리·새 권한 경계와 D-019는
  남는다. 안전한 자체 API 폴링을 fallback/롤백으로 제안하고 외부 SDK 재활성화를 기본값으로 삼지 않는다.
- 근거/검증: [SSE 추가 분석](ANALYSIS_REPORT.md#sse-migration)의 파일 지도와 로컬 실행 조건.
  실제 SSE endpoint·DB revision·브라우저/프록시는 구현·검증하지 않았다.

### D-019 — 자체 SSE의 영속 변경 감지·복구·운영 상세 계약

- 상태: pending
- 날짜: 2026-09-06
- 담당: 실시간·데이터·보안·운영 통합 책임자; 이벤트 보존 요구는 현장 운영 책임자
- 결정 필요 시점: 프롬프트02에서 단계/의존성을 정리하고, 해당 SSE 구현 단계 전에 확정
- 우선 제안: 동일 출처 EventSource, Django async 스트림, 거래에 포함된 영속 revision,
  워커당 공유 확인 허브, 권한이 적용된 일관된 snapshot. 별도 외부 메시지 서비스는 도입하지 않는다.
- 핵심 선택: 최신 대기 상태 복구만 필요한지, 모든 중간 전이·소리 알림·감사 재생이 필요한지.
  전자는 revision 우선, 후자는 outbox와 보관/재생/중복 계약을 비교한다.
- 구현 관문: 서비스 writer 통합 대 DB trigger, 전역 대 범위별 revision·old/new 대상,
  외부 SQL/SQLite 개발 경로, revision+도메인 잠금 순서·멱등 전체 재시도, snapshot 격리/캐시,
  generation 복원 절차·허브 수명. DB trigger나 Redis/Channels를 자동으로 승인하지 않는다.
- 연결 관문: CONNECTING의 native 재시도와 CLOSED의 제한된 재생성, 인증 fetch·세션 저장소
  오류 시 발행 상한, 역할 변경 때 큐/화면/이전 응답 폐기, 같은 generation의 revision 역전 방어.
  폴링 종료는 heartbeat 수신이 아니라 감지 허브 정상과 완전한 snapshot 적용으로 판단한다.
- 기존 대기 결정과 연결: D-003의 역할별 payload/발생 빈도 노출, D-006의 ASGI·DB풀·프록시,
  D-007/010의 지연·heartbeat·폴링/재시도·탭 수명·인증 회수 목표, D-008/011의 writer 범위,
  D-016의 복원/롤백을 확정해야 한다. 1초 revision poll·15초 heartbeat는 비교용 제안값이다.
- 검증: BK-R035~040의 writer·다중 워커·커밋/응답 역전·권한 회수·프록시·부하 인수 기준.
  로컬 async 응답 직접 순회는 실제 SSE 구현 통과를 대신하지 않는다.
- 독립 진행 가능: 기존 권한/조회/writer 특성화와 청사진 분할, 외부 연결 제거 대상 지도,
  재접속·완전한 대기 목록·안전한 폴링의 검증 설계.

### D-P04 — 자체 SSE의 단계 분할과 안전한 교체 경로

- 상태: proposed
- 날짜/담당: 2026-09-06, 기술·운영 통합 담당
- 근거: [SSE 추가 분석](ANALYSIS_REPORT.md#sse-migration), BK-R035~040, D-018.
- 제안: 3/4A 인가·세션, 5/6/7 writer, 8/9 snapshot 계약을10 SSE로 연결한다.
  12A의 최소 ASGI/프록시 실행 조건은10에 선행시킨다. 4B CDN/키 제거와10/11 주방 교체는
