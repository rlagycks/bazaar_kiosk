# 브라우저의 외부 Realtime 제거 (4B2)

상태: 로컬 구현과 검증. 결정은 [D-056](DECISIONS.md). 위험: BK-R018, BK-R029, BK-R020.
**스키마 변경과 마이그레이션이 없다. 외부 서비스 설정은 건드리지 않았다.**

## 무엇이 있었나

주방 화면은 세 가지를 하고 있었다.

1. CDN에서 외부 Realtime SDK를 내려받았다. 저장소가 고정하지 않는 코드가 운영자 화면에서
   실행됐다(BK-R029).
2. 프로젝트 URL과 익명 키를 **자기 HTML에 담아** 모든 주방 화면에 전달했다.
3. 그 키로 `orders_order`와 `orders_orderitem` 테이블 변경을 직접 구독했다.

세 번째가 핵심이다. Django의 신뢰 경계 옆에 두 번째 경계가 생긴다. 구독이 화면에 보이는 것보다
더 많이 읽을 수 있는지는 이 저장소가 검증할 수 없는 외부 Row Level Security에 달려 있었고,
익명 키는 RLS의 대체물이 아니다(BK-R018). 구독이 2초 안에 붙지 않으면 폴링으로 넘어가는
경합도 있었다.

## 무엇을 했나

| 이전 | 지금 |
| --- | --- |
| CDN `<script>`로 외부 SDK 로드 | 없음. 페이지가 여는 코드는 이 서버의 정적 파일뿐 |
| URL·익명 키를 HTML에 주입 | 없음. `_supabase_context`, 두 설정, `.env.example` 항목 제거 |
| 테이블 변경 직접 구독 | 없음. 화면은 자체 인증 API만 호출한다 |
| 구독 실패 시 5초 폴링 | 없음. 사용자 지시로 폴링도 함께 걷어냈다 |

## 자동 갱신이 없다는 사실

사용자 지시(2026-09-20): **"어차피 SSE로 갈 거고 지금 서비스 중이 아니니 폴링도 같이 없애자."**

그래서 10D의 자체 SSE가 들어올 때까지 주방 보드는 **스스로 갱신되지 않는다.** 바뀌는 경우는
세 가지다. 새로고침 버튼을 누를 때, 카드에서 취소·수량을 조작할 때, 그리고 탭으로 돌아올 때
한 번 읽는다. 탭 복귀는 타이머가 아니라 단발 요청이다. 탭을 열어 둔다고 폴링하지 않는다.

상태 줄은 이 사실을 **말한다.** "읽은 시각 hh:mm:ss · 대기 주문 N건 · 자동 갱신 안 함,
새로고침을 눌러 주세요". 멈춘 보드가 조용한 주방처럼 보이면 8B에서 막 고친 것과 같은 종류의
실패다. 갱신 시각을 앞세운 것도 같은 이유다.

## 외부 정리는 아직 남아 있다

**이 단계는 외부 서비스 설정을 하나도 바꾸지 않았다.** 브라우저가 더는 연결하지 않을 뿐,
외부에 남아 있는 권한은 그대로다. 아래는 **실행 목록이 아니라 인계 목록**이며, 각 항목은
별도 승인과 운영 담당자의 실행이 필요하다.

| 항목 | 왜 |
| --- | --- |
| Realtime publication에서 `orders_order`·`orders_orderitem` 제거 | 구독자가 없어도 발행은 계속된다 |
| 익명 역할의 테이블 권한·RLS 정책 재확인 | 키가 유출된 적이 있다면 구독 제거만으로 닫히지 않는다 |
| 노출됐던 익명 키 회수·재발급 | 이 저장소 이력과 배포된 페이지 소스에 실렸을 수 있다 |
| 외부 프로젝트 자체의 존치 여부 판단 | DB 이전(12A3)과 함께 결정할 사안이다 |

**BK-R018은 닫히지 않는다.** 위 목록이 실행되고 자체 SSE 인가까지 검증돼야 닫힌다.
BK-R029는 브라우저가 외부 코드를 더는 불러오지 않으므로 이 단계에서 닫는다.
BK-R020은 성격이 바뀐다. "연결 상실 후 폴링 복귀"가 아니라 "SSE 이전에는 자동 갱신 없음"이고,
10D에서 닫는다.

## 검증

```sh
.venv/bin/python scripts/test_postgres.py
```

`orders/tests/test_external_realtime.py`: 라이브 템플릿이 다른 origin의 스크립트를 열지 않음,
외부 서비스 토큰이 템플릿·뷰·설정·`.env.example` 어디에도 없음, 렌더링된 세 페이지에 외부 origin과
키가 없음, 반복 타이머를 만드는 코드가 없음, 화면이 자동 갱신 없음을 말함, 탭 복귀가 타이머가
아니라 단발 읽기임.

### 실행 중인 서버에 대한 HTTP 기록 (2026-09-20)

격리된 임시 PostgreSQL(포트 55471, 전용 compose 프로젝트)에 마이그레이션하고 개발 서버를
127.0.0.1:8010에 띄워 실제 요청을 보냈다. 검사 후 서버를 종료하고 `down -v`로 제거했다.
기존의 무관한 컨테이너는 건드리지 않았다.

| 검사 | 결과 |
| --- | --- |
| 로그인 후 `/orders/kitchen/`, `/order/`, `/b1-counter/` | 200, 각각 외부 origin `src`/`href` **0개** |
| 세 페이지의 supabase·cdn·realtime·createClient 토큰 | **0** |
| 세 페이지의 `setInterval` | **0** |
| 주문 생성 → 주방 보드 조회 | 201 → `mode=queue count=1 total=1 has_more=false` |
| 계정 비활성화 후 같은 토큰으로 보드 조회 | **401** |
| 비활성화 후 주방 페이지 | **302 → 로그인** |
| 비활성화 후 refresh | **401** |

**한계:** 이것은 HTTP 클라이언트 기록이지 실제 브라우저 네트워크 기록이 아니다. 이 환경에서
Chrome 확장과 Playwright 브리지가 모두 연결되지 않아 카드가 요구하는 V-BROWSER를 실행하지
못했다. 브라우저가 실제로 여는 하위 요청 목록, 끊김 상태의 화면 동작, 실기기 여정은 아직
검증되지 않았다. 배포 전에 실제 브라우저에서 한 번 확인해야 한다.

## 남은 것

- 위의 외부 정리 인계 목록. 승인과 운영 담당자의 실행이 필요하다.
- 실제 브라우저 네트워크 기록(V-BROWSER).
- 자체 SSE 서버·클라이언트와 재접속·응답 순서는 10D1·10D2.
- 그때까지 주방 보드는 수동 갱신이다. 실제 행사 운영 전에 SSE가 반드시 들어와야 한다.
