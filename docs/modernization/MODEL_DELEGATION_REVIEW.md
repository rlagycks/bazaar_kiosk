# 다른 모델에 대한 구현 위임 준비도 검토

2026-09-08 · 사용자 요청: Opus 5에 구현을 위임해도 되는지 검토만 수행.
**결론: 단계별 계획은 재사용할 수 있지만, 현재 문서를 그대로 넘겨 전체 구현을 지시하기에는 준비가 부족하다.**
모델을 바꾸기 전에 아래 인계 충돌과 승인·환경 조건을 정리해야 한다.

이 보고서는 저장소 문서의 실행 가능성을 평가한다. Opus 5를 호출하거나 실제 구현을
위임하지 않았고 모델 선택·실행 설정·기존 프롬프트를 변경하지 않았다. 사용자가 지칭한 모델의
정확한 서비스 식별자, 가용성, 도구 지원, 실제 구현 품질은 이번 검토로 검증하지 않았다.

## 재사용 가능한 기반

- [AGENTS](../../AGENTS.md)의 사용자 승인 우선, 데이터 보존, 의미 있는 검증은 특정 모델에 종속되지 않는다.
- [BLUEPRINT](BLUEPRINT.md)는35개 추적 단위의 선행 조건·범위·파일 소유권·인수 기준을 제시한다.
- 위험44개와 결정 상태를 분리해, 검증 통과·단계 완료·위험 해결을 구분한다.
- [로컬 테스트](TESTING.md), [PG fixture](POSTGRES_TESTING.md), [복구 후보](MIGRATION_REPAIR_REVIEW.md)의
  재현 자료를 사용할 수 있다. 새로운 모델에서도 같은 결과를 실제 실행으로 확인해야 한다.

따라서 현재 `03_IMPLEMENT_PHASE.md`만 복사해 “계획대로 구현”이라고 요청하는 방식은 적절하지 않다.
실행 프롬프트의 구체화는 별도 위임 준비 작업이며, 이번에는 원본 프롬프트를 재작성하지 않았다.

## 현재 상태를 전달할 때 반드시 포함할 내용

1. PR36·38 머지로2A/1A는 완료했다.1B 전체는 미완료이며2B를 완료로 취급하지 않는다.
2. PR40은0020 검토용 패치·후보 테스트를 담은 Draft다. 승인 전에는 원본 migration에 적용하지 않는다.
3. 0020만 승인되더라도0019의 과거 주문 삭제·테이블 재배정·제약 완화는 범위 밖이다.
4. PG 일일 미초기화(BK-R003)는 남으며0020 패치 승인과 번호 정책/운영 위험 수용은 다르다.
5. 원본 SQLite:19개 수집·12개 실행·PG7개 skip. 원본 PG: migration 모듈7개가 실패를 재현한다.
6. 후보 PG: 정확한 후보 클래스12개는 개선과 남은 실패를 함께 검증한다. 정상 흐름8개는 별도 실행한다.
   원본 PG 전체 suite 실패를 테스트를 삭제하거나 migration을 fake해 통과시키지 않는다.
7. 기존 CI는 check/drift다. CI 녹색을 후보 PG 테스트 수행 증거로 사용하지 않는다.
8. 새 작업마다 기준 ref·최신 변경·소유 파일·실행 명령·종료 조건을 명시한다.
   명령 실행이 막히면 미실행 이유를 기록하고 통과를 추정하지 않는다.

## 권고하는 위임 단위와 판단 범위

정확한0020 패치 적용 승인 후에만, 해당 파일의 최소 수정·성공 회귀 전환·원본 이미적용 경로
검증을 하나의 작업으로 맡길 수 있다.0019 정책·번호 정책·전체 현대화 구현을 묶지 않는다.
데이터/transaction/API 계약의 통합 책임자는 한 명으로 두고 결과 diff와 실제 실패/성공 출력을 검토한다.

현재 판정은 **인계 내용 보완과 해당 작업 승인 후 단계별 위임 가능**이다. 특정 모델이면
문제가 없다는 보장이나 Opus 5 실험 평가가 아니며, 실제 위임은 수행하지 않았다.
