# UI-11 전체 화면 통합 점검

기준일: 2026-09-22 · 기준: Figma 05안 + 확정 팀 댓글 · 브랜치 `ui/05-ui-acceptance`

UI-05A 서빙(PR81), UI-05B 모니터링(PR82), UI-05C 통계(PR83)를 한 업무 흐름으로 검증한다.
PR83은 독립 최종 리뷰(APPROVE, `9517bfc`)와 GitHub CI를 통과했다. 이 작업은 PR83을 기준으로
분리한 후속 PR이며, PR83을 먼저 합병한 뒤 develop 기준을 정리한다. 배포나 전체 단계11 종료는 아니다.

## 기기·브라우저 기준과 인수 경계

사용자 확정: **Chrome을 주 사용 기준으로 하되 Safari도 접속할 가능성이 있다.**
서빙은 휴대폰, 식당·포장 모니터링과 통계는 PC다. 여기서 실행한 브라우저 검증은 Codex 내장
브라우저의 viewport·키보드·DOM 접근성 구조 검사다. 실제 Android Chrome·iPhone Safari,
실제 소프트 키보드·VoiceOver/TalkBack을 실행한 결과로 대체하지 않는다.

| 범위 | 이번 결과 | 근거/한계 |
| --- | --- | --- |
| 주문→모니터링→통계 | 통과 | 합성 실제 HTTP/UI 주문과 별도 역할 통합 테스트 |
| 서버 오류 후 주문 입력 보존 | 통과 | 잘못된 테이블 거부 뒤 금액·품목 보존, 수정 후 재저장 |
| 서빙 좁은 화면 | 통과 | 390×844, 320×568, 높이 400. 가로 넘침 없음, 결제창 내부 스크롤·저장 버튼 노출 |
| 모니터링·통계 PC | 통과 | 1440×1000/1024×768. 내역·대화상자·권한별 업무 이동 |
| 키보드·접근성 구조 | 부분 검증 | Enter 준비 수량, Tab 이동, Escape 입력 보존, 명시 label·오류 초점. 실제 음성 낭독 미실행 |
| iOS/Android 실기기·소프트 키보드 | 미실행 | 현장 기기에 접근하지 못함. viewport 축소를 실제 키보드 검증으로 간주하지 않음 |
| Safari 호환성 | 미실행 | 실제 Safari에서 실행하지 않음. 아래 절차로 별도 인수 필요 |
| 운영 데이터·부하·배포 | 범위 밖 | 합성 데이터만 사용. 10E/12는 별도 |

## 발견과 수정

홀·포장에 같은 메뉴가 있으면 결제창의 수량/삭제 버튼과 모니터링의 준비 수량 버튼이
동일한 접근성 이름을 가졌다. 화면의 행을 함께 보지 않고 버튼 목록으로 탐색하면 어느 항목을
바꾸는지 구분하기 어려웠다. `홀 김밥 삭제`, `포장 김밥 준비 수량 늘리기`처럼 구분을 포함했다.
시각 디자인·금액·상태 규칙은 유지한다. 실제 controller 회귀 2개가 수정 전 실패하고 수정 후
통과했으며, 해당 이름으로 조작했을 때 선택한 품목만 바뀌는지도 확인한다.

## 재현 환경

운영 DB·기존 개발 DB를 쓰지 않는다. `compose.test.yaml`의 전용 제어 DB와 서버 사실 검사를
통과해야 UUID DB가 생성된다. 로컬 주소만 열며 Ctrl-C 종료 시 이 실행의 DB만 제거한다.
스크립트는 과거 브라우저 검증용 미추적 fixture를 재현 가능한 도구로 정리한 것이다.

```sh
BK_TEST_PG_PORT=55465 docker compose -p bk-ui11-local -f compose.test.yaml up -d --wait postgres
BK_TEST_DATABASE_URL=postgresql://bk_test_runner:synthetic-local-runner-only@127.0.0.1:55465/bk_test_control .venv/bin/python scripts/ui_acceptance_preview.py --port 8018
```

`http://127.0.0.1:8018/orders/login/`에서 `ui-all` 또는 `ui-serving`, `ui-hall`, `ui-takeout`,
`ui-stats`로 로그인한다. 합성 비밀번호는 `test-event-password`다. 모두 테스트 전용이며 운영에
공급하지 않는다. 10개 메뉴, 오늘 행사일, 홀 1/12와 포장 101–120을 준비한다. 시작 주문은 없다.
일반적으로 서버 종료 전에 검증 탭을 닫는다. 탭의 SSE가 열려 있어도 Ctrl-C로 종료할 수 있다.
서버는 별도 프로세스에서 실행하고, 그 프로세스의 종료를 기다린 뒤 UUID DB를 제거한다.
종료 후 이번 Compose만 정리한다.

```sh
BK_TEST_PG_PORT=55465 docker compose -p bk-ui11-local -f compose.test.yaml down --volumes
```

자동 검사는 [PostgreSQL 격리 절차](POSTGRES_TESTING.md)의 전체 launcher와 CI의 Node 명령을 따른다.
`orders.tests.test_ui_workflow`는 각기 다른 4개 권한 계정과 CSRF를 사용해 실제 API로 주문을 생성하고,
모니터링 범위·버전·수량·출발·재개·취소·통계를 함께 대조한다. 권한 거부가 주문/통계를 바꾸지
않는지와 연습 주문의 매출 제외도 검증한다. DB·API는 모의 처리하지 않는다.

## 브라우저 인수 절차와 예상 결과

1. `ui-all`로 390px 서빙을 연다. 홀 김밥 2개, 포장 김밥 1개·국수 1개를 담으면 합계 5,000원이다.
   홀·포장 버튼 이름이 구분되는지, 10개 메뉴·긴 메뉴명·HTML 형태 문자열이 안전하게 보이는지 확인한다.
2. 결제에서 테이블 12, 혼합 현금 4,000원·식권 2,000원 → 거스름돈 1,000원. Escape로 닫고
   다시 열어 입력 유지. 320px·낮은 높이에서 스크롤해 모든 입력과 저장 버튼에 접근한다.
3. 테이블 999999로 저장하면 서버 오류에 초점이 가며 품목·결제 입력은 남는다. 12로 고쳐
   저장하면 한 주문이 생성되고 초안은 초기화된다.
4. 내 메뉴→식당 모니터링에서 혼합 주문 확인. 홀 김밥 준비 1개 저장 후 여전히 준비 중이다.
   명시적으로 서빙 출발하면 준비 4/4, 미완료 0건·이력 서빙 출발이다.
5. 통계: 1건·4개·매출 5,000원·현금 4,000원·식권 2,000원·거스름돈 1,000원·순현금 3,000원.
6. 서빙에서 포장 김밥 1개, 번호101, 현금2,000원을 저장한다. 포장 모니터링에는 이 주문만 나온다.
   출발 후 전체 모니터링 이력에는 두 주문이 남는다.
7. 첫 주문을 준비 중으로 되돌리고 취소한다. 취소 상세는 조회만 가능하고 통계는 1건·1개·매출
   1,000원·순현금1,000원·취소1건이 된다. 실제 UI 확인과 별도 권한 HTTP 통합 검증을 구분해 기록한다.
8. 단일 권한 계정으로 허용된 업무 메뉴만 표시되고 다른 화면에 직접 접근하면 거절되는지 확인한다.
   내 메뉴 닫기/Escape 초점 복귀와 POST 로그아웃을 확인한다.

실기기 인수에서는 위 순서를 실제 Chrome에서 먼저 실행하고 Safari에서도 반복한다. 숫자 키패드,
확대·화면 회전, 키보드가 열린 채 저장/오류 접근, VoiceOver/TalkBack의 홀·포장 이름·오류 읽기,
백그라운드 복귀 후 최신 목록을 확인한다. 기기·OS·브라우저 버전과 결과를 기록해야 종료할 수 있다.

## 이번 실행 결과

- PostgreSQL 전체 launcher: 마이그레이션 27 + 애플리케이션 598 = **625 통과**.
  system check 정상, migration drift 없음. CI와 같은 Node 검사 **100 통과**.
- 위 브라우저 절차 1–7을 합성 데이터로 실행했다. 8은 서빙 단일 권한 메뉴·통계 직접 접근
  로그인 복귀, 전체 권한의 메뉴 Escape 초점 복귀·로그아웃을 확인했다. 네 역할의 API 거부와
  데이터 불변은 별도 PostgreSQL 통합 테스트로 확인했다.
- SSE 활성 상태에서 Ctrl-C 한 번과 연속 두 번 모두 종료 코드 0과 이번 실행의 UUID DB 제거를 확인했다.
  초기 단일 프로세스 구현은 연결이 남아 DB 제거에 실패했다. 서버 프로세스를 분리한 뒤
  재검증했으며, 앞선 실패 DB까지 포함한 이번 전용 Compose 볼륨을 마지막에 정리했다.
- 실기기·Safari·음성 스크린리더는 미실행이다. 전체 단계11 완료로 표시하지 않는다.
  상세 실행 기록은 [WORKLOG](WORKLOG.md)의 UI-11 항목을 따른다.
