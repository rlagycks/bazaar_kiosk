사용자가 **05안을 UI로 채택하고 코드를 적용한 뒤 추가 요청을 순차 반영**하도록 지시했다.
[05 · 레퍼런스 반영 수정안](https://www.figma.com/design/lrCdmOhZQfKiUIfz76tXvt?node-id=2135-907)이

## UI-05A의 실제 변경

- **로그인**: 이름+행사 공용 비밀번호 계약을 유지하고 05안의 차분한 녹색 계열로 교체했다.
- **내 메뉴**: 서빙 헤더에서 대화상자를 연다. 개인 이름, 허용된 업무 링크, POST 로그아웃을
  제공한다. 전체 모니터링은 식당·포장 권한이 모두 있을 때만 나온다. 서버 인가가 최종 경계다.
- **메뉴**: 홀·포장별 선택 수량을 `− 숫자 +`로 조절하고 `담기`로 확정한다. 선택 기본값은 1,
  담은 뒤 다시 1이다. 선택만 바꾸면 장바구니가 바뀌지 않는다. 같은 메뉴도 홀·포장을 구분한다.
- **결제**: 고정 하단에 합계와 `결제하기`. 대화상자에서 테이블 번호 바로 아래 담은 메뉴를
  펼쳐 보여 주며 수량 조절·삭제, 현금·식권·혼합, 거스름돈과 부족 금액을 표시한다.
- **입력 보존**: `돌아가기`·Escape는 닫기만 한다. 비우기는 확인을 받고, 화면 이동/로그아웃은
  미저장 주문을 확인한다. 저장 중에는 편집·중복 제출을 막는다. 새로고침 이후 보존은 제공하지 않는다.
- **실패 복구**: 실패·불명확한 성공 응답에는 초안을 유지한다. 같은 제출 내용은 같은 요청 ID,
  실제 제출 내용 변경은 새 ID로 보낸다. 서버의 일반 텍스트 검증 오류도 안전한 텍스트로 표시한다.

UI 추정 금액보다 서버의 가격·결제 검증이 우선한다. 기존 JWT 자동 갱신/기기 결속, CSRF,
주문 번호·연습 배지·전체 취소·URL을 유지한다. 외부 JS·폰트 서비스를 추가하지 않았으며
설치된 시스템 글꼴을 사용하므로 Figma 글꼴과 자폭이 다를 수 있다.

## 모니터링에 적용할 확정 의미

**완료 = 음식 준비 후 손님께 서빙 출발.** 손님 전달 완료를 뜻하지 않는다.
UI-05B에서 수량 충족만으로 READY가 되던 전이를 제거했다. 명시적 출발 확인이 모든 준비
수량·READY·출발 시각을 함께 기록한다. 기존 READY는 출발 미확인으로 표시한다.
[모니터링 구현·API·복구](UI_MONITORING.md), D-063을 따른다.
이력 상세의 편집 범위는 준비 수량·상태이며 메뉴/주문 수량/가격/부분 취소를 추가하지 않는다.
취소 이력은 조회 전용이다. 기존 전체 주문 취소 진입은 유지한다.

## 추가 수정 요청 처리

05안을 기준으로 변경 화면·변경 이유·업무 규칙 영향·검증 결과를 기록한다. 기존 흐름 안의
문구/배치 조정은 해당 UI 단계에서 반영한다. 금액·권한·상태·삭제 정책을 바꾸는 요청은
결정 기록과 관련 서버 테스트도 갱신한다. 비교안 전체를 자동으로 제품 요구로 채택하지 않는다.

## 검증과 인수 범위

- Node: `node --test scripts/test_order_state.cjs scripts/test_order_controller.cjs scripts/test_request_id.cjs scripts/test_dom_helpers.cjs`.
  수량 선택/담기 분리, 99개 경계, 홀·포장 구분, 재시도 ID, 결제 계산, 안전한 DOM을 검증한다.
  실제 controller를 가짜 DOM/fetch에서 실행해 일반 텍스트/JSON 오류·통신 실패·불명확한 성공 응답,
  명시적 재시도·중복 클릭·저장 후 초기화·혼합 금액 입력의 초점 이동을 검증한다. 새 테스트는 CI에 포함했다.
- Django: [전용 PostgreSQL 검사](POSTGRES_TESTING.md)의 `scripts/test_postgres.py`.
  권한 16조합의 메뉴 표시, CSRF/이스케이프, 기존 인증·주문·결제·SSE 계약을 포함한다.
- 브라우저: 합성 PostgreSQL/계정/10개 메뉴로 로그인→혼합 주문→결제 입력→닫기/재진입→저장,
  오류 보존, 권한 메뉴, 390px/320px 너비와 낮은 높이에서 검사한다. 결과는 WORKLOG에 기록한다.
- 실기기 iOS/Android, 실제 소프트 키보드와 음성 스크린리더는 후속 인수다. 브라우저의
  viewport/키보드/접근성 트리 검증만으로 실기기 인수를 완료했다고 보지 않는다.

UI-05A에는 DB 스키마·운영 데이터 변경이 없었다. UI-05B는 0030 마이그레이션이 있으며
복구는 UI_MONITORING의 정방향 수정 원칙을 따른다. UI-05A만의 롤백은 템플릿·정적 파일만 되돌리며 기존 인증,
안전한 DOM, 요청 ID 보호를 유지한다. 후속 사용자 지시로 브랜치 push·PR 생성을 진행하며,
merge와 배포는 포함하지 않는다.
