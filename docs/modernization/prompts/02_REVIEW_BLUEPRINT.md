# 프롬프트 02 — 적대적 블루프린트 검토

권장 모델: GPT-6 Astra

권장 추론 수준: `xhigh`

`ANALYSIS_REPORT.md`, `RISK_REGISTER.md` 및 중요한 비즈니스 결정이 준비된 후에만
이 프롬프트를 실행하세요.

```text
적대적 아키텍트의 관점에서 Bazaar Kiosk 현대화 블루프린트를 검토하고 수정하세요.
AGENTS.md와 docs/modernization/ 아래의 모든 현재 파일을 읽으세요. 여기에는
ANALYSIS_REPORT.md, RISK_REGISTER.md, 승인됨(accepted) 상태의 결정 및 WORKLOG.md가 포함됩니다.

목표는 숨겨진 맥락 없이 새로운 GPT-6 Astra 작업이 한 번에 한 단계씩 실행할 수 있는
구축 계획을 만드는 것입니다. 이 작업은 계획/문서화 작업입니다. 애플리케이션 코드를
구현하거나, 의존성 또는 마이그레이션을 변경하거나, 원격 Git/GitHub 상태를 변경하거나,
배포하거나, 프로덕션 데이터를 건드리지 마세요.

다음 파일을 업데이트할 권한이 있습니다.

- docs/modernization/BLUEPRINT.md
- 사용자가 이미 제공한, 검토된 제안 또는 승인됨(accepted) 상태의 선택을 기록할 때의
  docs/modernization/DECISIONS.md
- docs/modernization/WORKLOG.md
- 일반 실행 규약을 검토된 블루프린트에 맞춰 변경해야 하는 경우에만
  docs/modernization/prompts/03_IMPLEMENT_PHASE.md

먼저 현재 계획을 증거에 비추어 검증하세요. 누락된 의존성, 하나의 PR로 처리하기에 너무
큰 단계, 서로 겹치는 쓰기 범위, 순환 의존 관계, 검증할 수 없는 종료 기준, 안전하지 않은
마이그레이션 또는 롤백 가정, 무심코 결정된 비즈니스 규칙 및 연기하거나 제거해야 할 작업을
찾으세요. 점진적 현대화가 부분 또는 전체 재작성보다 여전히 더 안전한지 명시적으로
검증하세요.

각 단계에는 자체 완결적인 맥락 요약, 승인된 범위, 예상 파일 또는 소유권 경계, 선행 조건,
작업 목록, 인수 기준, 검증 명령/환경, 마이그레이션 및 롤백 전략, 관측 가능성에 미치는
영향, 보안 영향 및 인계 산출물을 요구하세요. 모든 치명적/높음(Critical/High) 위험을 하나의 담당
단계에 매핑하고 문서 사이에서 어떤 위험도 사라지지 않도록 하세요.

안전하게 병렬화할 수 있는 작업을 찾아내되, 긴밀하게 결합된 스키마, 트랜잭션 및 API 계약
변경을 소유권이 충돌하는 여러 담당자에게 나누지 마세요. 병렬 작업의 통합 책임자를
지정하세요.
원격 Git 정리는 별도의 승인 관문이 있는 작업으로 유지하세요.

빅뱅 방식의 재작성, 측정하지 않은 최적화, SQLite만으로 입증한 데이터베이스 동작,
테스트 개수 부풀리기, 명시되지 않은 API 변경 및 “올바르게 작동함”과 같은 모호한 종료
기준을 거부하세요. 정방향 전용(forward-only) 마이그레이션을 기본으로 삼으세요. 공개된 마이그레이션
산출물의 1단계 수정은 사용자가 정확한 수정 내용을 명시적으로 승인하고 계획이 신규 설치
경로와 이미 적용된 경로를 모두 입증하는 경우에만 허용됩니다. 적용된 마이그레이션 기록을 그 밖의
방식으로 수정하는 계획은 거부하세요. 문서화된 목표에 안전하게 도달하는 가장 작은 단계
순서를 선호하세요.

사용자 결정이 아직 없다면 그 결정에 의존하지 않는 모든 계획 섹션을 완성하고 정확한
관문을 표시하세요. 계획을 실질적으로 바꿀 결정만 질문하고, 일상적인 계획 세부 사항의
승인을 사용자에게 요청하지 마세요.

완료하기 전에 위험-단계 매핑의 누락 여부를 교차 확인하고, 모든 Markdown 링크를 검증하고,
git diff --check를 실행하세요. WORKLOG를 업데이트하세요. 최종 응답에서는 블루프린트의
실행 가능 여부를 먼저 밝히고, 중요한 변경 사항을 나열하며, 핵심 의존 경로와 병렬 단계를
제시하고, 실제로 필요한 다음 결정 또는 단계 승인만 요청하세요.
```
