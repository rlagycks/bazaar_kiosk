# 프롬프트 04 — 최종 통합 및 릴리스 준비 상태 감사

모델 공통 실행 계약과 과거 설정 구분은 [세션 안내](../SESSION_SETUP.md)를 따릅니다.
모델과 도구 설정은 실제 실행 환경에서 확인하며 다른 제공자의 인수를 그대로 사용하지 않습니다.

```text
Bazaar Kiosk 현대화의 최종 적대적 통합 및 릴리스 준비 상태 감사를 수행하세요.
AGENTS.md와 현재의 모든 현대화 보고서, 결정, 위험, 블루프린트 단계, 작업 로그 항목 및
릴리스/런북 파일을 읽으세요. 최종 브랜치를 승인된 정식 기준과 비교하고, 최신 커밋만이
아니라 모든 실질적인 변경 사항을 조사하세요.

이 작업에서는 감사를 우선합니다. 배포, merge, push, GitHub 설정 변경, 기록 재작성,
자격 증명 교체 또는 프로덕션 데이터 접근을 하지 마세요. 광범위한 정리 작업을 시작하지
마세요. 의도한 동작이 승인됨(accepted) 상태의 결정과 회귀 테스트로 이미 뒷받침되는 경우에만
범위가 명확한 작은 결함을 수정할 수 있습니다. 그렇지 않으면 증거와 함께 릴리스 차단
요인이나 후속 작업으로 기록하세요.

다음 관문을 감사하세요.

- 승인됨(accepted) 상태의 모든 비즈니스 불변 조건 및 운영자 핵심 여정
- 경로 수준의 인증, 인가, CSRF, 세션, 입력, XSS, 비밀 정보, 의존성, 서드 파티
  스크립트 및 Supabase RLS 가정
- 결제/합계/상태/멱등성의 정확성과 실패 응답
- 신규 설치 및 업그레이드 경로의 PostgreSQL 마이그레이션, 제약 조건, 일별 번호
  부여, 경합, 재시도, 롤백/완화, 백업 및 복원
- API 호환성, 오류 계약, 프런트엔드 렌더링, 접근성, 대상 기기, 오프라인/재연결,
  중복 제출 및 실시간/폴링 동작
- 재현 가능한 의존성, CI, 정적 검사, 집중/단위/통합/브라우저 테스트, 핵심 경로의
  테스트 범위 및 무의미한 테스트의 부재
- 문서화된 프로덕션 유사 워크로드로 측정한 쿼리/지연 시간/부하 예산
- 구조화된 로그, 민감 데이터 가림 처리, 헬스/준비 상태 확인, 메트릭, 경보, 배포 순서,
  롤백 및 운영자 런북
- 위험-단계 매핑의 종결 여부, 결정 추적성, Git diff 품질 및 의도치 않은 범위 밖
  변경 사항이 없는지 여부

협업 도구를 사용할 수 있다면 보안, PostgreSQL/데이터 무결성, 성능/실시간 처리,
프런트엔드/운영자 UX 및 릴리스/운영을 독립적인 검토자들에게 병렬로 맡기세요. 각
검토자에게 중복 코드 검토가 아닌 서로 겹치지 않는 감사 질문을 주세요. 각 검토자의
증거를 통합하고 서로 모순되는 발견 사항을 해결하세요.

필수 환경에서 문서화된 검사를 실행하세요. 각 실패에 대해 정확한 명령/워크로드, 출력
요약, 영향을 받는 불변 조건, 심각도, 재현 가능성 및 가장 작고 안전한 수정 방법을
보고하세요. 실패한 검사와 실행하지 않은 검사를 명확히 구분하세요. SQLite를 PostgreSQL
동작의 증거로 취급하거나 사용할 수 없는 프로덕션 의존성을 통과한 것으로 취급하지 마세요.

docs/modernization/FINAL_AUDIT.md와 RISK_REGISTER.md를 만들거나 업데이트한 다음
WORKLOG에 항목을 추가하세요. FINAL_AUDIT.md에는 각 관문에 대해 통과(Pass), 실패(Fail),
실행 안 함(Not run), 수용된 위험(Accepted risk)의 네 가지 상태 중 하나를 사용하는 추적 가능한
진행 여부(go/no-go) 표가 있어야
합니다. 릴리스 위험은 사용자만 수용할 수 있습니다.

완료하기 전에 git diff --check를 실행하고 문서 링크를 검증하세요. 최종 응답에서는
진행 가능(GO), 진행 불가(NO-GO) 또는 조건부 진행 불가(CONDITIONAL NO-GO)를 먼저 밝히고,
릴리스 차단 요인을 심각도순으로
나열하고, 통과를 뒷받침하는 증거를 요약하고, 실행하지 않은 검사를 식별하고, 가장 작은
다음 작업을 제시하세요. 핵심 불변 조건이나 필수 환경이 검증되지 않은 동안 GO를 선언하지
마세요.
```
